# Upstream

This repository is a fork of [ivarvong/lantern](https://github.com/ivarvong/lantern) at `2c7bad533be25fbd56d26a9a2b6c5651743f011e`. Lantern's README and its engine notes (verification, performance, flowcharts, the JSON document format) are at that commit: [README](https://github.com/ivarvong/lantern/blob/2c7bad533be25fbd56d26a9a2b6c5651743f011e/README.md), [docs](https://github.com/ivarvong/lantern/tree/2c7bad533be25fbd56d26a9a2b6c5651743f011e/docs). Some of what they describe was deleted here: the development player, the Worker site, the nine original scenes, `DocScene` and the JSON format, Lantern's own Mermaid parser and layout, and the tools that served them. The explainers in `scenes/explainers/` rebuild Lantern's examples. Lantern's panels in `src/panels.ts` (`title`, `CodePanel` and `StateReadout`) were deleted too. `StateReadout` came back for a while as the readout a view of state draws, and is gone again: a readout is now a `Card` without a panel.

From Lantern, with the changes below: `src/` (the engine), `tools/repo/fonts.sh`, `tools/repo/vendor-glyph.ts`, `tools/oracle/` (from Lantern, only `manim_math.py`; the fork added `glyph-math.ts`) and `tools/lib/browser.ts` (now only Chromium discovery and launch). The rest is the fork's: `explain/`, `integrations/agentic-mermaid/`, `app/`, the other tools and `scenes/explainers/`. The MIT notice in `LICENSE` is Lantern's.

## October 2026 backport

The fork base remains `2c7bad533be25fbd56d26a9a2b6c5651743f011e`. The engine backport reviews Lantern through [`d65fd1d`](https://github.com/ivarvong/lantern/commit/d65fd1da5f11f8e902b43eaf2e1598decee9abcb), specifically [#3](https://github.com/ivarvong/lantern/pull/3) and [#4](https://github.com/ivarvong/lantern/pull/4). It does not merge the repositories or change that ancestry.

It carries the Text advance-box correction, single-admission hierarchy rule, literal font-name validation, XML/own-property hardening and fill-only stroke omission. Rayner's scene admission also preserves repeated-root ordering within a batch and extends the rule to front/back and replacement entry points. Its live DOM patcher handles text changes independently of cached attributes and tracks prototype-sensitive own attribute names.

The layout checks are adapted rather than copied wholesale: Rayner's diagram labels are outline Groups, its connectors are VMobject paths, and its camera is a `Frame` object. The checker follows actual painted ink, clips, stroke width, draw order and opaque label plates. Imported labels have the same collision obligations as native text. Existing content-sized cards and diagram routing remain with Rayner and Agentic Mermaid; this backport does not add a second layout engine.

The Worker/JSON service, Cloudflare tooling and Lantern's fixed portrait-camera API are not included. Its blanket crossfade and phone composition policies would reject deliberate Rayner effects and teaching diagrams, so they are not adopted. Local SVG export retains widths above 4096px; that service-oriented ceiling is not needed here. SVG option formats are documented in the [reference](REFERENCE.md#engine-output-and-admission).

[The testing follow-up](https://github.com/adewale/rayner/blob/d3db60dc14124472903c0366ef64a819d57f2fe7/docs/evidence/upstream-backport/README.md) records why the earlier tests missed these bugs, the corrected contracts and the validation limits. WebKit's stroke fix is present; actual Safari execution remains separate platform evidence.

## Merging

```sh
git remote add upstream https://github.com/ivarvong/lantern   # once per clone
git fetch upstream
git log --oneline 2c7bad5..upstream/main                        # what is new upstream
git merge upstream/main
```

A file this fork deleted (the player, `src/doc.ts`, `src/mermaid.ts` and the rest) comes back as a modify/delete conflict when upstream changed it; keep the deletion with `git rm` unless the change belongs in the engine. After a merge, run `npm run check`, `npm run test:full`, `npm run test:embeds` and `npm run demos:check`.

## Engine fixes and zero-dependency features from the Rayner fork

This offers the general engine work from a downstream fork, [adewale/rayner](https://github.com/adewale/rayner) (Rayner, first named Lantern Explainers), back to Lantern. It touches `src/`, its tests and engine docs only. It adds no runtime dependency, renames or removes no export, and keeps Lantern's contract: every frame is a pure function of alpha over endpoints fixed at `begin()`, so a seek renders the frame a full run renders. Each animated feature below has its own seek test, and `test/public-names.json` lists the new names.

**Where it comes from.** adewale/rayner, then named adewale/lantern, forked this repository at `2c7bad533be25fbd56d26a9a2b6c5651743f011e`. Each item says which of the fork's branches made it: `explainers-reader-pass` (the fork's PR #1, its product layer) or `claude/intelligent-mendel-8djvkt` (PR #2, engine features, merged onto PR #1). The full diff includes the fork's product layer; this PR is the engine part of it. The fork deleted Lantern's player, Worker, scenes, `DocScene` and Mermaid parser, and removed engine code they used (`TextSink`, the `DomSink` frame-log hooks, `VMobject.validateCaches`, `Mobject.alignWith`, `summarizeMotion`), and Lantern's `title` and `CodePanel`; none of that is in this PR.

**Goldens.** `Step.hold` (feature 2) adds a `hold` field to every step with a caption hold, so each golden trace in `test/golden-traces.json` changes once; rewrite them with `UPDATE_GOLDEN=1` after looking. Nothing else changes a trace of a scene that records no evidence: `StepRecord.evidence` is present only on steps that recorded some, and none of Lantern's scenes uses an animation that records. Check `bench/baseline.json` on this branch; the fork no longer carries the bench.

### Fixes

1. **Nested `AnimationGroup.mobjects`.** A group inside a group contributed no mobjects, so `play()` animated objects it never added to the scene. The getter now flattens nested groups. Test: `test/core.test.ts`, "a nested AnimationGroup adds every leaf mobject to the scene". Branch: `explainers-reader-pass`.
2. **`FadeOut` restores the original opacity.** `finish()` set every member's opacity to 1, so showing faint artwork again (opacity 0.14) made it opaque. It now restores each member's starting opacity. Test: `test/lineage.test.ts`, "fade: FadeIn and FadeOut keep each family member's own opacity, 0 included (manim-web #467, #502)". Branch: `explainers-reader-pass`.
3. **`interpolate` of optional style fields.** Interpolation walked the current style's keys, so a field only the target had was never introduced, a field only the source had lerped toward `undefined` (NaN), and there-and-back easing could not restore it. Fields are now read from the fixed endpoints: numbers lerp, other values switch at alpha 0.5, and a field missing from the target is removed exactly at the end. This ships with the optional SVG paint fields on `Style` (`lineCap`, `lineJoin`, `fillRule`, `dashArray`, `dashOffset`, `miterLimit`, `paintOrder`) that imported artwork needs, with matching cache invalidation. Test: `test/core.test.ts`, "Transform adds and removes optional SVG paint at exact endpoints, there-and-back included". Branch: `explainers-reader-pass`.
4. **`Mobject.clipBox`.** A fixed, world-coordinate rectangular paint viewport, inherited by descendants (nested boxes intersect) and kept by `copy()`. It clips paint, not geometry, and a leaf wholly outside its clip is not written, because resvg 2.6 aborts on a translucent element its clip leaves no area. It was needed because zoomed artwork painted over a heading. Tests: `test/explain-clip.test.ts` (nested and translated output, rasterised with the optional `@resvg/resvg-js`; seek identity). Branch: `explainers-reader-pass`.
5. **`Mobject.pointKind()`.** Point arrays blend only with the same kind, so a line morphing into a `Text` no longer ends on its advance box. Test: `test/property.test.ts`. Branch: `explainers-reader-pass`.
6. **A `Transform` from a container into a single path** drew nothing. The path now moves into a child of its own first, as Manim's `null_point_align` does. Test: `test/property.test.ts`. Branch: `explainers-reader-pass`.
7. **`parseColor`** reads `#rgba` and `#rrggbbaa` and returns `null` for anything else; interpolation produced `#NaNNaNNaN`. Test: none of its own; in the fork only an explain test (`test/explain-helpers.test.ts`) calls `parseColor`, through the explainer palettes, so add an engine test of the three forms when cutting the branch. Branch: `explainers-reader-pass`.
8. **Fixes from Manim's and manim-web's issue history**: `runTime: 0` shows the end state, the clock comes from the frame count, `replace()` leaves no ghost, groups do not ease twice, dashed strokes keep their dashes while drawn, `Code` expands tabs, the shaping memo is bounded, and others. Each test in `test/lineage.test.ts` names the issue it comes from. Branch: `explainers-reader-pass`.
9. **Missing glyphs.** Text outside the embedded fonts was blank with no error; `takeMissingGlyphs()` reports the characters drawn as nothing. `shaperFor` and `StopScene` are exported. Tests: in the fork the report is covered by an explain test (`test/explain-gates.test.ts`, the missing-glyphs gates); `test/fonts.test.ts` checks it stays empty for the numerals the fallback faces draw, and `test/public-names.json` lists the exports. Branch: `explainers-reader-pass`.
10. **State JSON keys.** `stateJson()` (`describe()` in that branch) copies the keys of each added part as own keys and refuses a part that returns no object; a `"__proto__"` key became the result's prototype. Test: `test/scene-hooks.property.test.ts`. Branch: `explainers-reader-pass`.
11. **`play()` with a lone `.animate` builder.** A builder is a Proxy, and it reported `Object.prototype`, so `play(box.animate.shift(RIGHT))` with no trailing options took the builder for the options object and animated nothing. Builders now have a prototype of their own. Test: `test/lineage.test.ts`, "play: every .animate builder given to play() animates, the last one too (ManimCommunity #4865, #1129; manim #1618)". Branch: `explainers-reader-pass`. In `claude/intelligent-mendel-8djvkt` the `Mobject` and `CodeSpan` builders share `animateBuilderBase()`; test: `test/anim-utils.test.ts`, "play() with a lone .animate builder animates it (it is not the options object)".
12. **A stop that cannot be swallowed.** A seek ends its run by throwing `StopScene` from the sink. A `construct()` with a broad `try`/`catch` (the ring buffer scene, rebuilt downstream, had one for its own `Full` error) swallowed the stop and went on emitting frames into the seek, so jumping to a step showed a different frame from playing to it. A `StopScene` from a sink now sets `scene.stopped`, and `play()`, `wait()`, `step()` and `emitFrame()` rethrow it before beginning anything. Plain code between the catch and the next scene call still runs. Tests: `test/timeline.test.ts`, "a swallowed StopScene cannot emit frames: a seek still renders the played frame" and "after a stop, play(), wait() and step() reject at once without reaching the sink"; both fail with the flag disabled. Branch: `claude/intelligent-mendel-8djvkt`.
13. **The motion verifier's cut-in rule.** A leaf that appears over a leaf that stays and is no less opaque is no longer a cut-in when it is a `TransformFromCopy` copy of that leaf, or when every shown part of it has the same `shapeKey()` and the same fill and stroke presence as a part of the staying leaf. A brighter shape over a faint one, a filled shape popping inside an outline, a hand-made `Transform(t.copy(), other)` that changes glyph shapes on its first frame, or a shape appearing elsewhere still is. Tests: `test/anim-utils.test.ts`, "a copy over its source is no cut, but a brighter shape over a faint one still is" and "a cut-in is exempt over a staying leaf only when it is a copy of it or looks the same"; the `test/verify.test.ts` calibration is unchanged. Branch: `claude/intelligent-mendel-8djvkt`.

## Agentic Mermaid

The build pins Agentic Mermaid 0.5.1 as an authoring dependency; pages never load it. Natural diagram lettering uses its public `TextMeasurementProfile` host hook. Rayner measures the scene's actual faces and cuts before layout, then checks that the imported SVG advances match the outlines it draws. Cached natural diagrams also record the source-font and measurement-policy identity.

`integrations/agentic-mermaid/capture.ts` still registers a capture backend through `registerBackend`, renders through `createMermaidRenderer`, and keeps each mark's `drawNode` output. Capture must equal the upstream renderer byte for byte, using the same text-measurement profile. Agentic Mermaid 0.5.1 also exports `renderResolvedScene`; migrating the existing importer to that public parts API is separate work.

The earlier 0.4.1 limitations around late node labels and state-family reporting are fixed upstream. Rayner retains a diagnostic for a rendered bare node id that contradicts an explicit source label. The catalog and capture tests exercise the pinned renderer; changing it requires real snapshot recapture and review of all supported families.

For natural captures, `verifyMermaid` supplies source diagnostics and semantic endpoints only: its default-font layout cannot certify Rayner's custom geometry. Rayner checks the captured geometry, label collisions and visible routes, and reviews the actual served paint at both reader widths.

## Agentic Mermaid state edits

Two limitations found while building the statecharts lesson are tracked upstream:

- [#596](https://github.com/adewale/agentic-mermaid/issues/596): `make_composite` fails after `remove_transition`.
- [#597](https://github.com/adewale/agentic-mermaid/issues/597): no edit creates a concurrency region.

The reports include reproduction snippets and pinned links to the original renderer-validation controls. Observations cover versions 0.5.1, 0.5.5 and 0.5.6.
