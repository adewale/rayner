# Look up an authoring feature

Each row names an authoring feature, the code an author writes for it, and a catalogued explainer that uses it, linked to the file where it does. Read that file to see the feature in place: its imports, the state it draws from and the step it belongs to. [The reference](REFERENCE.md) lists every option, and [its entry points](REFERENCE.md#testing-and-tooling-api) say what each is for. Most names come from `rayner`; `stage`, `settingsOf`, `palette` and `view` from `rayner/explain`; `bars`, `code` and `pin` from `rayner/drawing`; and `seenFrom` and `between` from `rayner/geo`. In the code column, `this` is your `Scene` and `s` is `stage(this)`.

The table is rendered from `lookup` in [`test/public-names.json`](https://github.com/adewale/rayner/blob/main/test/public-names.json) by `node tools/repo/public-names.ts --write`, and the files it links are found from each row's names and patterns in the explainer's code. `test/public-names.test.ts` fails when the page differs from what the ledger renders, when an explainer a row names is not in the catalog or uses none of the row's names and patterns, when the code column names an exported name the row does not list, and when an explainer starts to use a name its row says no explainer uses yet. The [engine feature inventory](REFERENCE.md#engine-features) is the same kind of table by engine area, listing every explainer that uses each name.

## Features that need setup

- **Maths:** [float-sum](https://github.com/adewale/rayner/blob/main/scenes/explainers/float-sum/scene.ts) asks for `lettering: { math: true }` in its `static meta` and sets two formulas with `MathTex`, drawn from outlines committed in its `scene.lettering.json`. Capturing new ones needs the pinned Latin Modern Math font and `rayner snapshots`, as [Maths](REFERENCE.md#maths) describes.
- **Additional writing systems, faces, weight and italic:** [string-length](https://github.com/adewale/rayner/blob/main/scenes/explainers/string-length/scene.ts) asks for `lettering: { scripts: ['Deva', 'Hebr', 'Arab', 'Hani'], styles: ['bold'] }`, and [font-metrics](https://github.com/adewale/rayner/blob/main/scenes/explainers/font-metrics/scene.ts) for a replacement face with real bold and italic. Each captures and commits `scene.lettering.json` as described in [Lettering](REFERENCE.md#lettering-on-request); Arabic, Devanagari and Hebrew, replacement faces and real bold or italic use the [outline workflow](LETTERING.md#supported-requests).
- **Played scores:** the [melody and rhythm scene](https://github.com/adewale/rayner/blob/main/scenes/explainers/melody-rhythm/scene.ts) draws both piano rolls from the note data supplied to `step.audio`. Sound starts only after a reader gesture; see [score audio](REFERENCE.md#optional-score-audio) for clip limits and cancellation.
- **Diagram families and geometry:** change `source` in `s.show({ source: 'graph LR\nA --> B' })` to another supported family, and call `d.reveal`, `d.walk`, `d.enlarge` or `d.morph` as the story needs. For natural font measurements, set `s.show({ source, lettering: 'natural' })`; it needs a requested face and refreshed snapshots. See [diagrams](REFERENCE.md#diagrams) and [measurements](LETTERING.md#diagram-measurements).
- **Event-driven models:** a [`Machine`](MACHINES.md) replays events through your model, and `rayner check` draws every state they reach.

A passing `rayner check` shows that every scenario seeks correctly, stays legible and has words for every drawing. It does not show that your explainer's claims are true, so test the domain model on its own before publishing. To write an explainer from the start, follow the [tutorial](TUTORIAL.md), which builds one of LRU and MRU cache replacement.
