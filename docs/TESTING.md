# Testing Rayner

The primary Linux/current-Node lane owns the full property, source-vector, raster, Chromium transport/interaction and installed-capture suites. Linux/Node 24.0.0 retains the standard suite and full Chromium reader boundary for minimum-runtime drift. All six compatibility profiles keep a fresh installed-package check, including TypeScript consumption, diagram/PNG authoring, snapshot replay and watched preview. That preserves the OS/filesystem/native-binary boundary on Intel and ARM Mac without repeating every pure property on each profile.

The ARM Mac/current-Node lane additionally runs `test/reader-cross-browser.test.ts`: Playwright WebKit checks served paint for every case of the cache, token-bucket, PKCE, requested-face and music examples; the bundled macOS `safaridriver` checks the actual Safari browser’s introduction, case changes, requested lettering and iframe reader. Set `EXPLAIN_WEBKIT=1` or `EXPLAIN_SAFARI=1` to reproduce those checks. WebKit mobile emulation is not physical iPhone testing. Keep a real-device check of touch, zoom, rotation and VoiceOver before claiming those behaviors on iOS.

`npm run check:budgets`, after `demos:check`, validates the exact built hashes and records three fresh Chromium samples each for the cache, rate comparison and largest example, at 390 px and 4× CPU slowdown. It uses the existing benchmark recorder, with an 8-second median startup ceiling. `out/validation/page-budgets.json` retains all samples and the CPU/browser configuration. This is a localhost CPU surrogate, not a physical-phone or network-loading result. Every build separately enforces 1.5 MiB raw HTML and 450 KiB gzip limits.

The phone comparison test requires the complete readable cache/rate result in one opening at both 320 and 390 px, retaining the 12 px floor. Their independent served-paint claims require the counts and rejection marks in that opening. The detailed token balance/curve description remains checked at the `later` step; the final `trace` step now checks the three outcome rows instead of the removed overlaid curves. Existing model-state and view-fidelity assertions still cover all five steps at every rate.

The `player (motion …): any burst …` properties in `test/explain-embed.test.ts` own early controls, resting-picture/direct-link comparisons and mid-motion scene reuse. Their generator includes every step and case of PKCE, exgit and mr-cache, plus a counted scene that detects replay. The scheduled audio property in `test/explain-audio.test.ts` owns pending resumes and sound cancellation on navigation, Stop and Pulse changes.

The reader model also checks resize operations across the 600px stage boundary. Its fixed regression starts at a 632px viewport, resizes to 390px and zooms; the reverse sequences start at 200px and 390px, resize to 632px and back before pressing the corner map. It runs at 400px and 1200px heights: the taller viewport asserts that the actual stage reaches 600px, since the short viewport can cap even a wide stage at 320px. Every tour stop checks pan as well as scale. Tour choices must use the new stage dimensions while active zoom, step and history stay put. This sequence failed against stale desktop tour metadata before the repair. Keep the complete generated viewport/action domain alongside it.

`test/view-readouts.test.ts` owns the four detailed token readouts and the final comparison’s thirty outcome marks against an independently fixed schedule. The geometry test delegates values to that owner. `test/release-publish.test.ts` is the single publication-guard owner; both npm and GitHub executables and registry responses are isolated fakes, including the pre-existing wrong-tag, dirty-source, lettering-gate and filename rejections. The render-cache test retains its original frame cadence and also samples the first eleven frames, so a short scene receives enough independent cache-free comparisons without lengthening the product’s animation.

Run `npm run check` and `npm test` on Node 24 or later. `npm run test:full` increases generated-case counts. `npm run test:embeds` enables the real Chromium reader tests; set `CHROMIUM_EXECUTABLE_PATH` when Chromium is installed outside Playwright's cache. Lettering capture tests additionally need the pinned fonts and Python requirements described in [LETTERING.md](LETTERING.md). A skipped optional check supplies no pass evidence.

The suite uses fast-check for generated inputs and shrinking. `test/lib/pbt.ts` owns the seed and run-count policy. Generated tests complement the checked-in upstream vectors, Manim/raster references, browser integration and installed-package checks. These boundaries catch different failures; agreement between two calls to the same implementation is a weak substitute for an independent expected value.

`npm run demos:check` builds and checks the catalog. `npm run demos:review` then serves that exact output and visits every resting step of every settings case at 390 and 1180 pixels. It rejects stale build inputs and incomplete case inventories. Each width opens fresh; subsequent steps use the reader controls and wait for the matching ready event. The receipt counts every step/width row, and screenshots preserve each opening.

The story review checks declared subjects and fresh helper emphasis, falling back to changed artwork when neither exists, against actual SVG paths, computed paint, native bounds and clips at each close-up stop. Independent caption claims additionally name important subjects and opening requirements, including the OAuth attack arrows and WCAG Focus Visible criterion. Named subjects must be complete. Helper-highlighted route shapes may enter an authored viewport; their labels must remain whole and every highlighted subject must contribute visible ink. Explicit arrow claims remain whole. Incidental context may pass through an authored viewport; its expected visible portion comes from the source frame and must be reachable in actually painted views. A caption over unchanged artwork must declare a subject. Rectangle-union properties use an independent integer-cell oracle; browser controls reject missing, transparent, clipped and selectively hidden subjects.

The [story coverage audit](evidence/story-coverage/README.md) records the new owners and failing controls. CI separates catalog generation from three all-step story jobs and retains the exact build and review artifacts. It runs after failed dependencies and fails explicitly rather than being skipped. Use `npm run demos:review -- --shard N/3` for each part, then `node tools/explain-review-merge.ts` to reproduce the combined check. A job cancelled before acquiring a runner is infrastructure failure, not test evidence: inspect its check annotations and retry it.
