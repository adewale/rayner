This closes that counterexample; it does not establish equivalence for every Git mode, which the script explicitly excludes.

## Picture fidelity: executable verification

Run from the checkout, after `npm ci`:

```sh
node docs/evidence/verify-view-fidelity.ts
```

This runs the real `collectProject` and `checkProject` pipeline. A view includes a correctly state-derived counter label and a polygon. Each probe manually changes one visible property before frames are drawn. An independent SVG comparison establishes that the probe actually changes the output. The view's state-dependence check is active because the counter reads state.

| Probe | SVG changed | `checkProject` result at the reviewed source |
| --- | --- | --- |
| Clean control | No | Passed |
| Red fill changed to green | Yes | Passed |
| Black stroke changed to green | Yes | Passed |
| Square changed to triangle with the same bounding box | Yes | Passed |
| Half the polygon clipped away | Yes | Passed |
| Draw fraction reduced to 0.3 | Yes | Passed |
| Polygon moved 0.25 units | Yes | Rejected by Views |

Thus the comparison's omissions are observable false negatives, not merely a concern inferred from source. The position control shows the actual view gate runs. Frame seeking and hold checks can agree on consistently wrong pictures. The separate dependence probe checks whether drawing depends on state, not whether every rendered property currently matches it.

This experiment does not identify a visibly wrong current catalog scene or test the served browser-review pipeline. It uses ordinary views; machine transitions also have rendered-target checks. The reusable experiment reports outcomes without requiring these gaps to remain as permanent passing behaviour.

The initial recommendation, now implemented below, was to strengthen ordinary view fidelity. Compare stable rendered records, including styles, path data and effective clips, with an equivalently placed fresh draw. Preserve meaningful geometry tolerances, inherited placement, paint order and font shaping, and exclude incidental renderer identities. Add deliberately stale and correctly synced cases for every covered property. Evaluate false positives on the catalog before expanding the guarantee.

## What the experiments support

The [premise benchmark](../../bench/premise/README.md) tests factual claims. Its six-topic totals include unverifiable claims:

| Page | Right | Wrong | Unverifiable | Total |

The plain authors were forbidden research. Method-only authors reused scripts, models, tests, answers and evidence, and read the completed Rayner explanation. These controls show that the tested factual grounding can survive removal of the animation/rendering engine. They do not isolate research from oracle testing or establish cheaper independent authoring without Rayner. The Poppy method-only page retains small refusal machinery; it is not literally free of every Rayner function.

The blind second grader regraded 314 grouped items representing 490 claims from rounds 2 and 3, including method-only pages, not every item in the aggregate headline. It agreed on 311 items. Both graders were models from the same family; no human validation or learning test was conducted.

There is measured delivery value: the two method-only phone pages had 8.5/9.3 px text, plus clipping or overlap, while Rayner reached 12 px via close-ups. Rayner's whole picture was also too small. That supports the close-up and layout-checking machinery, not a demonstrated improvement in comprehension. Classifying 21/33 checks as portable is not proof that porting them is free.

The [explainer comparison](../../bench/explainers/README.md) measures a blind model reviewer's page preference. Three earlier plain pages won both rounds; round two reused those plain pages and rebuilt the same Rayner scenes. Those are not six independent replications, current-product results, or learning outcomes. No subsequent comparison after the later player and machine changes is recorded.

The narrow conclusion is that the method supplies demonstrated factual grounding on these examples. The engine supplies concrete interaction, rendering and delivery features. Its incremental effect on independent author effort and reader understanding remains unmeasured.

## Animation module responsibilities

At the reviewed commit, `src/animation.ts` has 2,493 lines. The concern is change coupling, not a file-length rule:

| Responsibility | Reviewed lines |
| --- | --- |
| Lifecycle, phase, timing validation, cleanup, evidence | 179–367 |
| Endpoint transforms, fades, creation | 388–853 |
| Parallel/staggered schedules | 872–993 |
| Path movement and emphasis | 1004–1139 |
| Sequential schedules, deferred construction, beats/actions | 1141–1851 |
| Key/text/shape matching, glyph grouping, longest runs, Hungarian assignment | 1853–2317 |
| Diff-driven code transforms, hunk validation, line pairing | 2319–2493 |

Scheduling and lifecycle are coupled for valid reasons: an animation must capture endpoints at its turn, wait for layout, clean up failures and preserve deterministic seeking. Splitting classes arbitrarily could introduce cycles and additional exposed internals. No runtime defect was established merely by this module's breadth.

When a concrete maintenance need arises, pure matching/assignment or line-planning algorithms are the safest extraction candidates. Preserve deterministic tie-breaks, exact endpoints, traces and error behaviour. No wholesale split is justified by this review alone.

## Motion-corpus interpretation

[The corpus guide](../MOTION-CORPUS.md#what-this-score-establishes) records the scoring limits. Its 59 entries are reconstructed historical mutations from one eight-chapter Poppy series: 24 direct reversals and 35 adaptations. They are not a recoverable one-to-one list of the issue's original 63 findings. Rules were tuned against these same examples.

| Detector | Before | After |
| --- | ---: | ---: |
| Jump | 1 | 1 |
| Flicker | 2 | 3 |
| Covers | 0 | 19 |
| Small words | 0 | 3 |
| Early words | 0 | 0 |
| Total | 3 | 26 |

The result-before-cause hit is detected as a jump, not by the early-words detector. A hit is any baseline-new finding; it need not identify the original defect. The existing full gate preserves all 26 named entry IDs, which is stronger than preserving only the total. The fast gate samples three detector kinds.

The 33 misses are: ten drawing/non-token/no-current-overlap cases; one overlap below the 0.1-second threshold; eight layout-motion cases; thirteen with no applicable rule (three long, three squeezed, one glyph dissolve, four causality/stale-result, two separated duplicates); and one explicitly excused flicker. These categories mix mechanical limits and meaning. An engine draw-order occlusion bug lies outside the scene-mutation corpus. Longer or shorter motion is not inherently defective; rejected timing rules also flagged accepted transitions.

Edit applicability alone does not prove the adapted variant still shows the intended defect. Future scores should retain affected frames and expected rule/transition/part identities, run baseline subtraction, and add independently discovered prospective cases. Passing checks cannot replace editorial review of meaning and pace. This follow-up reran the applicability and three-detector sample tests, not the complete 59-entry campaign.

For a controlled comparison:

1. Freeze the question, script, independently tested model, oracle, evidence and allowed research identically for both arms. Neither author sees a finished page. Choose new topics, including an interactive system and a simpler static case.
2. Randomly assign or counterbalance independent authors to current Rayner and a simple state-to-SVG/HTML implementation. Separate agent-author results from human-author results; hold available help and resources constant.
3. Record end-to-end author time, tool/resource use, code changes, assistance, failures and fixes, successful delivery, accessibility/readability defects and factual outcomes. Reusing a finished model is a rendering comparison, not the total cost of discovering the model; report those phases separately.
4. Give learners a prior-knowledge assessment and a no-lesson control. Randomly assign pages, then assess unseen transfer tasks and delayed retention where feasible, with blinded grading and prespecified primary outcomes. Page preference is a secondary measure, not a learning score.
5. Set sample size from a stated effect of interest and practical recruitment constraints before collecting outcomes. A small pilot estimates feasibility and variance; it does not warrant a general learning claim. Report exclusions, uncertainty and unsuccessful builds, and retain artifacts.

No participants or new learning results are available in this task. The actionable next step is preparing a study using the actual release candidate, then deciding what to simplify from observed friction and outcomes.

## Implemented comparator and rendering comparison

The view gate now preserves its structural checks and also compares the shown and freshly state-drawn SVG records: tag, sorted attributes, path data, paint order, transform, text and effective rectangular clipping. It uses the renderer's numeric precision, ignores generated identities and memoized strings, and normalizes equivalent hex colour spelling. It renders a projection without changing either picture's ownership or scene roots. The state-dependence probe now recognizes changes confined to paths or clips.

The executable fidelity experiment now accepts the clean control and rejects all five formerly accepted changes; its position control still rejects. Owning gate tests add stroke width, dash, alpha and paint-order mutations, plus acceptance controls for equivalent colours, fresh identities, inherited placement/clips and state-dependent paths. These compare against Rayner's Node renderer, not an independent browser raster or proof that a caption is true.

Catalogue checking exposed an actual mismatch at the seasons example's `latitude` step: it manually thickened both latitude lines to 0.09, while a fresh state draw still produced 0.05/0.07. The draw now derives the emphasis from the recorded daylight-table state, and the scene synchronizes its views. The example's own regression checks both months across all four scenarios against a fresh draw. Its full project check passes.

The [executable rendering comparison](../../bench/rendering/README.md) freezes two new subjects (lower-bound search and circular FIFO), two conditions each, independently tested models, all step states, words, questions, geometry and a pinned font. One arm uses standard Rayner stage/steps; the other uses native SVG and a small script with navigation, case selection, links and transcript. It asserts that the native bundle imports no engine/player modules. Both arms must pass factual admission before browser measurement; failed oracle output is retained.

The [retained run](../../bench/rendering/results-2026-11-17.json) contains source/engine/font/input hashes, source commit and dirty status, oracle output, frozen inputs, artifact bytes/hashes, all 96 conformance rows and 48 timing samples. Both widths pass exact content/paint checks, the visible-label threshold (minimum 13.42 px), overflow, page-error and external-request checks. The native pages are about 81% smaller gzipped in these fixtures. Median phone ready times were 549.4 versus 163.6 ms for lower bound and 321.0 versus 133.8 ms for FIFO (Rayner versus native). Catalogue validation ran concurrently; these small local samples are descriptive, not a stable speed ratio or performance guarantee.

This establishes a reproducible rendering comparison with controlled inputs. It does not measure outside-author effort, learner understanding, custom machine-event interactions or editorial motion quality. The participant protocol above remains necessary before claiming an advantage in authoring or learning. Neither these results nor the motion-corpus score alone warrants an engine rewrite.
