# Why couldn't these users find the command?

A participant is asked to carry out a file-management task. The command exists in a menu, but the participant does not complete the task. Follow where that command was located, then compare the report's account of where people looked. Having a command available is not the same as making it discoverable.

The opening follows the selected participant's first unfinished task: changing icon size, Select All or Undo. Each case shows a schematic route to the relevant control, not a screenshot of the Files interface. The accompanying observation comes from the study: for example, the people who gave up on Undo had not opened its menu.

Did everyone struggle in the same way? Compare all six participants on that task. Some completed it with little difficulty, others reported or demonstrated greater difficulty, and some could not complete it. Those are different outcomes. An approach excluded as outside the study's scope is different again; it is not another failure score.

The fuller task record places those observations in each person's session. All six had at least one unfinished task in this study, and those unfinished tasks were among the menu tasks. The list-view and search tasks came at different points in the session from their task numbers, so session order matters when reading the journeys.

These observations concern six first-time GNOME users working with test builds of Files 47. They can identify specific places to investigate, but they do not measure failure rates for all users, establish how long a task took or show that a later version behaves the same way.
