Statecharts, explained
Step 1 of 12

A statechart is a state machine whose states can contain other states

It adds two things to an ordinary state machine:

  1. A parent. A state can be a box of states, a parent. Any event its children don’t handle goes to the parent.
  2. Regions. A state can be split into regions, each in one state at the same time.
State
what the thing is doing right now, such as idle or playing.
Event
something that happens, written in capitals, such as POWER_OFF.
Arrow
“if this event arrives while in this state, move to that state.”
State machine
states joined by arrows. It is in exactly one state at a time.
What comes next

Each addition solves a different problem. We start with the problem parents solve, using a coffee machine.

Where a plain state machine hurts

Here is a coffee machine as an ordinary state machine. It loops through four states: idle, grinding, brewing, ready. Press an event button and watch the filled state move.

Now give it a power button. POWER_OFF has to work in any of the four states, and POWER_ON brings the machine back.

The cost

Four copies of one arrow: same event, same destination. Every time you add a state to the loop you must remember another copy. Forget one and the power button silently stops working there. Try POWER_OFF in each state to see them all work.

Put the four in a box, draw the arrow once

Idle, grinding, brewing and ready all do the same thing on POWER_OFF. So put the four in a box called on and draw POWER_OFF once, from the box. A box of states is a parent; the states inside are its children.

The rule

When an event arrives, ask the state the machine is in. If it has no arrow for that event, ask its parent, then the parent’s parent, until someone does.

The machine is in brewing right now.

Notice the machine is in brewing and in on at once: brewing sits inside on. Press other events to explore. Powering on enters on, which starts at idle.

The same pattern, one level deeper

This is not just a coffee trick. Here is a phone app. While signed in you can be at home or in settings, and settings is itself a box holding account and privacy.

SIGN_OUT is drawn once, on signed in. BACK is drawn on settings (go home) and also on privacy (go to account).

You are on the privacy page right now.

The pattern, anywhere
  1. Spot an arrow repeated on several states.
  2. Put those states in a box.
  3. Draw the arrow once, on the box.

An arrow on an inner state still beats the same event on an outer one, because inner states are asked first. Try SIGN_OUT from privacy: it climbs two levels.

Two independent choices

A music player has two separate facts about it. It is playing or paused. And it is muted or unmuted. Changing one never changes the other. Flip the switches:

What you are looking at

Four states and eight arrows for just two on/off features. Look at the arrows: every state carries its own copy of both flips. Press the events and watch the machine hop between combinations.

Every new feature doubles it

Add a third on/off feature to the player, say repeat. A plain machine is in one state at a time, so it needs a state for every combination of all three facts.

The pattern

Each new on/off feature doubles the flat machine: 2, 4, 8, 16, 32… With regions, each new feature adds one small two-state machine: 2, 4, 6, 8, 10… Drag the slider to see how far apart they get.

Booleans hide the same problem

Many programs skip state machines and keep flags instead: isPlaying and isPaused. Two flags can be set four ways. The player is always either playing or paused.

The hidden problem

Flags don’t forbid the impossible. A bug that forgets to clear isPaused when playback starts leaves both true, and nothing stops it. A region always holds exactly one of its states, so “playing and paused” is something you cannot write.

Regions: two small machines side by side

Split the player into two regions. Playback is one tiny machine (playing, paused). Volume is another (unmuted, muted). The player is in one state of each region at the same time.

The player is playing and unmuted right now.

What to notice

Every region is asked about every event, and each answers only the events it has arrows for. Four states and four arrows, instead of four states and eight. Add a third feature and you add a third region of two states, not four more combinations.

Nothing new becomes possible

A common misconception

“A statechart is a more powerful kind of machine that can do things an ordinary state machine can’t.”

How to flatten any statechart
  1. Copy each parent’s arrows onto every child inside it.
  2. Make one flat state for each combination of region states.

What is left is an ordinary state machine with the same behaviour. What you gain is a drawing the size of the idea instead of the size of every combination, so it stays readable as the product grows.

Remember this

Parents

Shared behaviour is written once, on the box, not copied onto each child.

Regions

Independent features sit side by side, so they add up instead of multiplying.

Nothing new

Flatten any statechart and you get an ordinary state machine that behaves the same.

A statechart is a state machine that can nest states and run parts side by side, so shared behaviour is written once and independent features don’t multiply.
