Does isdigit() guarantee int() can parse it?

You've probably written this, or seen it in a code review:

if s.isdigit():
    n = int(s)      # safe… right?
No. str.isdigit() says yes to some characters that int() refuses, such as "²" (superscript two) and "①" (circled one). So the guarded line can still raise ValueError. It also goes wrong the other way: it says no to strings int() parses happily, like "-5" and " 42 ". 
>>> "²".isdigit()
True
>>> int("²")
ValueError: invalid literal for int() with base 10: '²'

Why: "digit" means more than 0–9

Python strings are Unicode, and Unicode has many characters that stand for digits. The Unicode standard sorts them into groups, and Python's three "is it a number?" methods each check a different group:

  • isdecimal(): characters you write ordinary numbers with, in base 10. This covers ASCII 0–9 and also the digits of other writing systems: Arabic-Indic ٣, Devanagari ३, full-width ３, and so on.
  • isdigit(): all the decimal characters, plus characters that stand for a single digit but aren't meant for writing ordinary numbers: superscripts ², subscripts ₂, circled ②, and a few historical scripts whose digits don't work positionally.
  • isnumeric(): all of the above, plus anything with a numeric value at all: fractions ½, Roman numerals Ⅻ, Chinese numerals 五.

Why would int() refuse ² when it plainly means 2? Because a superscript isn't a digit you write numbers with. What should "1²" parse to: 12, or 1 squared? The safe answer is to refuse, and Python refuses.

It's wrong in both directions

As a guard, isdigit() is too loose (it lets through things that crash) and too strict (it blocks things that would parse fine). int() strips surrounding whitespace and accepts a sign and underscores between digits; isdigit() accepts none of those.

What to write instead

try:
    n = int(s)
except ValueError:
    ...  # not an integer

This is the usual Python answer. int() is the only thing that knows exactly what int() accepts, so let it decide. You also get signs and surrounding whitespace for free.

if s.isdecimal():
    n = int(s)

isdecimal() matches the set int() actually uses (and is the same as re.fullmatch(r"\d+", s) on a str). It still rejects "-5" and " 5", and it doesn't protect you from the length limit below. Use it when you want "only unsigned digits", not as a stand-in for "int() won't raise".

if s.isascii() and s.isdecimal():
    n = int(s)

If "٤٢" turning into 42 would surprise your database, log parser or ID check, add isascii(). Together they mean "only the characters 0 to 9".

One more trap: very long numbers

Since Python 3.11 (and in security releases of 3.7 to 3.10), int() refuses to convert a decimal string with more than 4,300 digits by default. This protects against a denial-of-service attack, because the conversion gets slow on huge inputs. So even "1" * 5000, which is plain ASCII digits and passes every check above, raises:

ValueError: Exceeds the limit (4300 digits) for integer string conversion: value has 5000 digits; use sys.set_int_max_str_digits() to increase the limit

That's one more reason to rely on try/except rather than a pre-check.
