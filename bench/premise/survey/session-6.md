1. **Yes, if its type is `Send`.** `thread::spawn` requires that, and the compiler checks it automatically. Moving a pointer is never the issue. The issue is who can reach the data afterwards. After you clone an `Arc<T>` and send one clone to another thread, both threads hold `&T` to the same value at the same moment. So `Arc<T>` is `Send` only when `T: Send + Sync`, where `Sync` means "safe for several threads to read through `&T` at once." That's why `Arc<RefCell<_>>` fails with E0277: `RefCell` isn't `Sync`, so the fix is `Arc<Mutex<_>>`. `Rc` is never `Send`, because its reference count isn't atomic. The general rule is that `&T` is `Send` exactly when `T` is `Sync`. (High confidence.)

4. **Git writes the whole new contents of the changed file, not a diff.** That's a compressed "blob" named by the hash of its contents. Git also writes new "tree" objects (directory listings) for each folder on that file's path up to the root, plus one small commit object pointing at the top tree and the parent commit. Every unchanged file and folder keeps the same hash, so the new snapshot just points at the objects already stored. That's why a snapshot is cheap. Later, `git gc` and packfiles compress similar blobs into deltas, but that's a storage optimisation, not the data model. (High confidence.)
